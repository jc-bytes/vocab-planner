# Selected school profile exports

Apply `20261025154305_filter_owned_school_profile_exports.sql` before publishing its client. The required-RPC readiness check includes `list_student_identity_roster_by_ids_school_owned_v1(expected user, school, user IDs)` as the ninth owned signature.

The new RPC retains the legacy roster's complete JSON projection, school permissions and global grade/section/name/user-ID order, while filtering to the requested IDs inside PostgreSQL. The existing full-roster endpoint and its permissions remain unchanged. There is no new count cap or client-side batching: selecting an entire school still uses one ordered request.

`teacherExportRepository.getProfiles` captures school, account and selection generation before awaiting initialization. Empty or invalid UUID selections do not initialize the backend or make a request. The ten-second deadline includes initialization and transport, checks the composed abort signal before dispatch after initialization, and discards results after an account or school change. Same-user auth refreshes remain valid. The server's expected-user check protects the later SDK token acquisition boundary; client checks alone cannot do that. Existing strict ID matching and profile/timestamp mapping remain in place, and account rewards are never added to exports.

Run `npm run test:selected-profile-export:database` against the local Supabase stack. The rehearsal clones schema definitions into a disposable database, creates only synthetic school/class identities, and tests exact equality with filtering the legacy roster. It covers 13 role contexts, duplicate/empty/null/mixed-school selections, selected 30 of 300 and 900 students, and a full 900-student selection with exact global order. Real SDK/PostgREST controls include a delayed same-user token refresh and a delayed replacement token from another authorized actor in the same school. Every legacy function definition, owner and ACL must remain unchanged.

The report records serialized JSON payload sizes and complete result hashes. It does not make latency or throughput claims during concurrent work. Disposable database, gateway, role and secret-environment resources are removed automatically; evidence is retained in the reported temporary directory. The rehearsal does not apply definitions to the default local database or contact hosted systems. Portable ownership/deadline controls are in `tests/teacher-profile-export-ownership.test.mjs`.
