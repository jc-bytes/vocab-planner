# Student service worker upgrades

The student worker downloads the complete student JavaScript and CSS graph after page load, including optional modules. Downloading code does not execute it. Initial student and teacher bundle budgets and lazy imports remain unchanged. Teacher-only code and large optional game media stay outside this precache. The current graph uses about 2.1 MB before compression; this extra offline transfer is separate from initial execution size.

Every emitted graph receives its own Workbox precache. A document leases the graph of the HTML it receives. New workers activate immediately, retain graphs needed by existing documents, and serve old immutable code URLs from those retained caches. Student navigation selects cached HTML and writes its resulting document's lease under the same scoped Web Lock as cache cleanup. A delayed navigation handled by a retired worker receives the latest cached HTML if its previous graph has already been removed.

Cleanup keeps the current graph and graphs leased by open documents. A navigation receives 30 seconds to become an enumerable window client. After a document closes or a navigation is canceled, its graph becomes eligible after that grace; cleanup runs on the next student navigation, activation, or subsequent fetch (ordinary fetches throttle cleanup to once per minute). Browser workers do not run reliable background timers after all tabs close. Installing graph caches are not cleanup candidates. Storage therefore follows live document graphs and pending navigations rather than the number of deployments.

Browsers without the Web Locks API retain old graphs conservatively because safe cross-worker eviction cannot be guaranteed. Browser storage eviction or exhausted storage can still remove offline data. The existing runtime caches for visited nonmanifest scripts, styles, images, and fonts remain available with their prior limits.

The first deployment of this repair cannot reconstruct an old release's optional code that was never cached and has already disappeared from the host. Already open legacy tabs must finish their current work and return to a safe menu for the existing automatic reload, or reload after saving. Subsequent full-graph releases protect unvisited old modules across upgrades. Deployment retention of old immutable assets is required to eliminate that initial compatibility gap; this local change does not deploy or retain host files.

Run `npm run test:ui:worker-lifecycle` for a fresh production build and a disposable four-version browser rehearsal. `STUDENT_WORKER_LIFECYCLE_REUSE=1` is reserved for a build freshly produced earlier in the same validation run. The check uses an ephemeral loopback port, cleans its temporary copies, and covers the legacy gap, unsafe work, safe-menu saving/reload, old lazy modules offline beyond runtime-cache expiration, newly visited scripts cached for offline use, client-version binding, in-progress installs, and closed-document cleanup. Unit tests also exercise both navigation/cleanup orderings and conservative fallback behavior.
