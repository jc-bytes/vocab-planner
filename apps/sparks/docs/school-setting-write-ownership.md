# School setting write ownership

Apply `20261025141012_bind_school_settings_writes_to_actor.sql` before publishing this client. It adds `set_school_setting_owned_v1` and `set_school_year_owned_v1`. Both are authenticated-only public invoker functions with an empty search path. They compare the captured actor with `auth.uid()` before calling the existing private mutation. Existing school permissions, audit behavior, legacy signatures, and legacy grants remain unchanged. The client has no unowned fallback.

Teacher gamification/calendar forms and school-admin calendar, archive, and reopen controls capture their actor and view guard before waiting. Writes share a deadline across lazy loading, initialization, and transport. A known replacement actor rejects locally; a replacement token selected later inside the SDK is rejected by the owned database function. A response already committed under the original authorized actor cannot be rolled back by local cancellation.

The local lifecycle guard compares Supabase's JWT `session_id` when available. Same-session focus/recovery `SIGNED_IN` events and token refreshes remain valid; a genuinely replaced session or sign-out cancels the operation. A late `INITIAL_SESSION` cannot replace a baseline established by a later event. Without an observable session ID, teacher-service reference/generation checks remain a cancellation fallback. Session claims are used for local cancellation only; server authorization still uses `auth.uid()` and existing private role checks. See [Supabase sessions](https://supabase.com/docs/guides/auth/sessions), [database function security](https://supabase.com/docs/guides/database/functions), and [AbortSignal](https://supabase.com/docs/reference/javascript/using-modifiers-abortsignal).

Run `node scripts/rehearse-school-setting-ownership.mjs` with the local Supabase stack. It clones schema definitions into a disposable database, applies the new migration there, and uses the actual SDK default token lookup against isolated PostgREST. The A-to-B races must return 403/42501 without changing settings, years, or audit rows. Normal original-admin saves and anonymous/legacy-ACL controls must pass. The script removes its database, gateway, temporary role, and environment file; it never mutates the default application's data or contacts hosted Supabase.

`npm run verify:owned-rpc-readiness` checks every required owned RPC, including both school-setting entry points. Run the existing deployment gate after applying reviewed migrations and refreshing the API schema cache. The verifier checks anonymous execution denial using valid dummy arguments; it applies no migrations and publishes nothing. Local source/unit and mocked administration UI checks do not establish hosted rollout readiness.
