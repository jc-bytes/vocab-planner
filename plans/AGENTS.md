# Planning Workspace Instructions

Apply [Technology Class Preparation Standards](00%20Navigation/Technology%20Class%20Preparation%20Standards.md) whenever creating, revising, or quality-checking plans, lesson packages, student work, or assessments in this directory.

## Plain-Language Methodology

- Write so the intended student can understand the first reading. Use the spirit of `Explain it like I'm five`: make ideas simple and concrete without sounding childish or removing grade-appropriate content.
- Give student-facing activities short, literal titles, usually two to six words. Prefer `Topic + Task/Product` or `Verb + Product`, such as `Internet Safety Poster`, `Build a Data Chart`, or `Scratch Score Game`.
- Use familiar words, active voice, and short sentences. Use one main action per numbered step.
- Start directions with direct verbs such as `Open`, `Write`, `Add`, `Create`, `Check`, `Save`, `Download`, and `Submit`.
- Explain a necessary technical word before asking students to use it. Remove jargon that is not part of the learning objective.
- Replace vague language with exact counts, names, examples, dimensions, formats, and visible evidence.
- Keep teacher-facing writing concise too. Define uncommon abbreviations and make the next action obvious.
- Apply a first-read test before marking an artifact `Ready`: the student should be able to say what to do first, what to make, what must be included, and what to submit.

## Google Classroom Assignments

- Treat paste-ready Google Classroom instructions as a required student-facing artifact whenever students must create, complete, demonstrate, or submit work through Classroom.
- Build the Classroom post from one approved assignment specification. Do not independently invent or paraphrase consequential requirements in the handout, template, example, checklist, presentation, or rubric.
- State the exact product, required content and counts, required wording, dimensions or duration, attachments, tools, filename, file type, submission evidence, group/individual responsibilities, and make-up or technology-failure path when applicable.
- Separate fixed requirements from valid student choices. Prescribe colors, fonts, or decorative layout only when the objective, accessibility, brand requirement, or teacher decision requires them.
- Do not use `See rubric for details`. A rubric may explain scoring levels but may not introduce a requirement absent from the Classroom post.
- Map every scored requirement to an announced Classroom direction. Map every required deliverable to a rubric criterion, checklist item, or explicit non-scored submission check.
- Verify that the template supports the directions and that the completed example follows them and earns its intended score.
- Do not mark the assignment or lesson package `Ready` while the Classroom post contains blanks, placeholders, contradictory requirements, missing attachments, or an incomplete submission method.
- Apply the absent-student test: a student should be able to complete and submit the task using only the Classroom post and its attached student files.
