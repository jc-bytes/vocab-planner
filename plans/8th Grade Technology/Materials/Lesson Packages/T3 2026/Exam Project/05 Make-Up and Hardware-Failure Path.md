# Scratch + micro:bit game make-up and hardware-failure path

This path preserves the project objective and the same rubric evidence. The teacher assigns the applicable route.

## Absence make-up

1. Read the project brief and complete the game plan.
2. Complete the missed milestone during the scheduled make-up period.
3. Use the same build and test log, required game behaviors, and reflection.
4. Demonstrate the project live to the teacher.
5. Submit the saved project file or approved share link and all typed records.

## Physical micro:bit unavailable

Use the teacher-approved simulator or Scratch keyboard controls as a temporary input. Label the input used. Add a sensor mapping table that states:

| Intended micro:bit input | Temporary input | Scratch action | Expected result |
|---|---|---|---|
| Button A | Left arrow | change x by -20 | Player moves left 20 |
| Button B | Right arrow | change x by 20 | Player moves right 20 |

Explain live how the temporary input would be replaced by the physical micro:bit. The game logic, testing, documentation, and presentation requirements do not change.

## Scratch or computer unavailable during class

Complete the paper game flow, block plan, variable table, and three traced tests. When computer access returns, transfer the fixed plan into Scratch and demonstrate one successful run. Paper planning alone is not the final project unless the teacher approves an accessibility accommodation.

## Internet or account unavailable

Use the local Scratch editor and save the project file to the teacher-approved location. Submit the file directly when Classroom access returns.

## Make-up verification

- [ ] Same game-design requirements
- [ ] Equivalent input mapping evidence
- [ ] Same code and game-logic requirements
- [ ] Same testing and debugging evidence
- [ ] Same documentation and reflection
- [ ] Live teacher check and responsible submission
