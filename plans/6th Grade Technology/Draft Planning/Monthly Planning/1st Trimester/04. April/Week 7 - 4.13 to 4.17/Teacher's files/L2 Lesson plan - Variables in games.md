# Lesson 2: Variables in programming

Enjoyed teaching these lessons? Found a mistake? Share feedback at the-cc.io/feedback.

# Introduction

Learners understand that variables are used in programs, and that they can only hold a single value at a time. They complete an unplugged task that demonstrates the process of changing variables. Then, learners explore why it is important to name variables and apply their learning in a Scratch project in which they make, name, and update variables.

# Learning objectives

To explain why a variable is used in a program

- I can identify a program variable as a placeholder in memory for a single value

- I can explain that a variable has a name and a value

- I can recognise that the value of a variable can be changed

# Key vocabulary

Variable, name, value, set, change

# Preparation

Subject knowledge:

- You need to know that a variable is a placeholder for a single value in the memory of a computer, and that all variables are uniquely named. These concepts are explained in the plan below.

- You need to know that when the value of a variable is updated, the original value is replaced.

You will need:

- L2 slides

- Devices capable of running Scratch 3

- A1 and AP– Individual whiteboards

- A1 Activity sheet – Update a value (or sticky notes and page 2 of the activity sheet)

- A3 Scratch project – Scoreboard (the-cc.io/scoreboard)

- A3 Scratch project – Scoreboard solution (the-cc.io/scoreboardsolution)

- A3 Handout – Exploratory task: Display a variable in a different way

# Assessment opportunities

Activity 1: You can assess whether learners can identify the name and value of a variable, and whether they can identify that variables can only hold one value at a time.

Activity 2: You can assess whether learners can choose suitable names for variables.

Activity 3: You can assess whether learners can create and change variables in a Scratch project. Through the explorer activity, learners can apply their previous experience of Scratch to display variables in a different way.

# Outline plan

Please note that the slide deck labels the activities in the top right-hand corner to help you navigate the lesson.

*Timings are rough guides

| Introduction<br>(Slide 3)<br>5 mins | Variables in a program<br>Display slide 3. Remind the learners that variables can be set and changed while the program is running.<br>Draw their attention to the screen recording on the slide. Ask learners what is changing during the game. They should identify that the score and the timer change during the game. In this example, they are both variables.<br>Some learners may identify that the positions of the ball and penguin also change during the game. Explain that this is achieved using Motion and Event blocks, and does not involve Variable blocks. |
| --- | --- |
| Activity 1<br>(Slides 4–6)<br>10 mins | What can a variable hold?<br>Display slide 4. Develop the definition of a variable: in addition to a variable being something that can be set and changed during the running of a program, explain that a variable is also a placeholder in the memory of a computer, and can hold one value at a time.<br>Explain that each variable in a program is named, as can be seen in the animation on the slide. Ask learners to write the name and value of the variables shown in the animation on their individual whiteboards.<br>Build the slide to reveal the correct names and values:<br>Name: Number, value: 162<br>Name: Favourite_food, value: Chocolate cake<br>Ask the learners why ‘Number’ is not a useful name for a variable. Explain that this is because if it were seen in a program, out of context, it would be meaningless. This question will be revisited on slide 6.<br>Display slide 5 and give learners the activity sheet (or some sticky notes and the second page of the activity sheet). Explain that they are to complete an unplugged activity to demonstrate that a variable can only hold one value at a time. Tell learners that they need to choose four values for the variables named ‘Favourite_food’ and ‘Number’. Once they have chosen their values, learners should cut out each ‘sticky note’. They should then add a value to the second page for each of the variables to create a sentence.<br>Display slide 6. Explain that the values in a variable can be updated. To do this, learners need to remove the original value (and destroy it) and replace it with a new value. Emphasise that the variable can only hold one value at a time, so you can’t have two sticky notes on top of one another.<br>Refer back to the question on slide 4 and ask the class what would be a better name for the variable ‘Number’ in this context. Learners should identify that the name should refer to it being the number of times that they eat a certain food in a day. For example, ‘Favourite_count’ or ‘Number_favourite’.<br>Note: When the value of a variable is updated in a computer program, there is no delay in changing between the original value and the new value. This is difficult to simulate away from a program. |
| Activity 2 (Slides 7–8)<br>5 mins | Naming variables<br>Display slide 7. Refer to the slide and ask learners, “Which drawer are the pencils in?”. At this stage, learners cannot give a definitive response. They could either guess, or check every drawer. Ask learners how the task could be made easier. Guide them to identify that it would be easier to find the pencils if the drawers had labels that could help them.<br>Build the slide to show the set of drawers. Ask learners to think, pair, share to discuss why these labels make it easier to find the pencils.<br>Display slide 8. Explain that variables are similar to drawers, in that they contain something (Note: A drawer can contain lots of things, but a variable can only hold one value at a time). Therefore, the name of a variable should identify what it holds. Variable names should be brief and should not contain spaces. Point out that the example on the slide has an underscore where a space would usually be (Home_team). Build the slide to show the example of a scoreboard, with the variables named. |
| Activity 3<br>(Slide 9–10)<br>15 mins | Make a scoreboard in Scratch<br>Display slide 9. Explain that learners need to make a simulation of a scoreboard that involves clicking on a sprite to change a score variable.<br>Direct learners towards the ‘Scoreboard’ Scratch project, which contains sprites for the flags of the USA and Japan.<br>Ask learners to use the design on slide 10 to create variables, add events, and decide how their variables will change. When choosing how their variables will change, learners need to select the variable that they have created from the change my variable by () block. For example:<br>Remind learners that when they name their variables, the names should be brief and not contain any spaces. Explain that one score should represent the home team’s score, and the other should represent the away team’s score.<br>Note: Typically, on a scoreboard, the home team will precede the away team. In this case, the order is not important.<br>Explorer task: Provide the learners with the handout. Ask them to use the blocks on the handout to experiment with a different way of displaying variables. By using the following code snippet, the sprites appear to ‘say’ the score:<br>Show learners the ‘Scoreboard solution’ Scratch project (it does not include the say block). In this project, click on the Variables blocks to show how each variable can be ticked or unticked to determine if the name and value of the variable are visible on screen.<br>Note: If some of your learners have completed the explorer task, you may want them to share how they used the say block to display a variable. As learners become more familiar with using variables, the projects should be designed to display the variable as part of the program. The tick box in the Variables tab is a great way to display a variable, but should not be a permanent solution.<br>Ask learners to save their projects. You can find guidance on saving projects in Scratch 3 in the unit overview. |
| Plenary<br>(Slides 11–13)<br>5 mins | Quiz time<br>Display slide 11 and ask the learners, “How many values can a variable hold?”. Ask them to record their responses on their individual whiteboards. Build the slide to reveal that the correct answer is A — a variable can hold one value at a time.<br>Display slide 12 and ask the learners, “What do all variables have?”. Ask them to record their responses on their individual whiteboards. Build the slide to reveal that the correct answer is C — all variables have a name and a value.<br>Display slide 13 and ask the learners, “When running a program, which part or parts of a variable can be updated?”. Ask them to record their responses on their individual whiteboards. Build the slide to reveal that the correct answer is B — when a program is running, only the value can be updated. |
