# Lesson 5: Design to code

Enjoyed teaching these lessons? Found a mistake? Share feedback at the-cc.io/feedback.

## Introduction

In this lesson, learners implement the algorithms that they created in Lesson 4. In doing this, they identify variables in an unfamiliar project and learn the importance of naming variables. They also have the opportunity to add another variable to enhance their project.

## Learning objectives

To use my design to create a project

- I can create the artwork for my project

- I can choose a name that identifies the role of a variable

- I can test the code that I have written

## Key vocabulary

Task, algorithm, design, artwork, program, project, code, test, debug

## Preparation

Subject knowledge:

- This lesson is based around the ‘levels of abstraction’ approach to design in programming, which is explained in the unit overview. In this lesson, learners begin at the ‘code’ level to create and name variables. They then work through all levels of abstraction, from the ‘task’ to ‘running the code’, to create their own game.

You will need:

- L5 slides

- Devices that are capable of running Scratch 3

- A0 – Individual dry wipe boards

- A0 Scratch project – Intro chatbot (the-cc.io/introchatbot)

- A1 Scratch project – Fruit catcher template (the-cc.io/catchertemplate)

- A2 Scratch project with code visible – Intro chatbot (the-cc.io/chatbotcode)

- A2 – Learners’ project designs from Lesson 4

- A3 Activity sheet – Project evaluation

- L5 Homework – Making a timer (Optional)

- L5 Homework solutions – Making a timer (Optional)

## Assessment opportunities

Introduction: You can assess whether learners can identify variables in an unfamiliar project.

Activity 1: You can assess whether learners can add artwork to their project based on their designs.

Activity 2: You can assess whether learners can choose appropriate names for variables and implement code based on their algorithms.

Activity 3: You can assess whether learners can test and debug their project.

## Outline plan

Please note that the slide deck labels the activities in the top right-hand corner to help you navigate the lesson.

*Timings are rough guides

| Introduction<br>(Slides 3)<br>5 mins | Identify and name variables<br>Display slide 3. Share the ‘Intro chatbox’ Scratch project with the learners. This is a ‘chatbot’ project, which is different to other projects that they have explored in this unit. Play through the project and ask the learners to note down on their individual whiteboards where variables might be used in the program.<br>Answers may include the following:<br>A variable is used to set the name<br>A variable is used to set the age<br>A variable is used to check the answers<br>Note: The variables to set the name and age have been added to the program. The variable to check the answers is a system variable that is available as a defined block in Scratch. Even though this block is found in the Sensing section of blocks, it is still a variable as it can be set and changed. |
| --- | --- |
| Activity 1<br>(Slides 4–5)<br>10 mins | Add artwork<br>Display slide 4. Hand out the learners’ Lesson 4 project designs. Remind the learners of their task on the slide. Ask the learners to think, pair, share, “What is the first thing you need to add to your project?”. Explain that in this activity, they will add the artwork for their projects using their designs. They need to add the two additional sprites and their background to the project.<br>Display slide 5 and direct learners to the link provided on the slide. Ask learners to create their own version of the project template and to add their artwork to the project. |
| Activity 2<br>(Slides 6–9)<br>15 mins | Create your project<br>Display slide 6. Before opening the Scratch project, explain to the learners that they will think, pair, share to suggest better names for the two variables shown on the slide. Open the Scratch project and run the chatbot program again, this time with the code visible. Give learners time to suggest alternative names for the variables. Learners should suggest ‘age’ for ‘variable_a’ and ‘name’ for ‘variable_b’.<br>Show slide 7 and explain that code ‘A’ is the code for the chatbot Scratch program they just saw. Build the slide and explain that code ‘B’ shows the same code with the variables named differently. Ask the learners to suggest which code is easier to understand.<br>Display slide 8. Remind the learners that they need to make sure they name their variables appropriately, to make them easier to work with.<br>Show slide 9. Remind the learners of their task and leave it visible on the slide. Direct the learners back to their Scratch projects. Ask them to implement their algorithms.<br>Encourage learners to work independently on their project. |
| Activity 3<br>(Slide 10)<br>10 mins | Run and debug<br>Display slide 10. Hand out the activity sheet. Ask learners to test and debug their project and record their findings on the activity sheet. In doing this, they need to be mindful of the original task — does the project deliver against the original requirement?<br>Ask learners to save their projects. You can find guidance on saving projects in Scratch in the unit overview. |
| Plenary<br>(Slides 11–12)<br>5 mins | How could your game end?<br>Display slide 11. Ask learners to think, pair, share, “How could your game end?”. Take some suggestions from the learners about how they could determine when their game ends.<br>Show slide 12. Share a new algorithm with the learners and ask them what they would name the variable, based on the algorithm. After a brief discussion, click to reveal the answer, and explain that ‘time’ or ‘timer’ would both be useful names. |
| Next time<br>(Slides 13–14)<br>5 mins | This time, next time<br>Review the ‘Assessment’ and ‘Summary’ slides. |
| Homework<br>(Optional) | Coding a timer<br>In the homework activity sheet, learners will complete code snippets for a timer where the names and values of variables, and the values for repeat and wait blocks, have been removed. The algorithms have been provided for three examples, and the fourth box is blank for learners to create their own algorithm and code. |
