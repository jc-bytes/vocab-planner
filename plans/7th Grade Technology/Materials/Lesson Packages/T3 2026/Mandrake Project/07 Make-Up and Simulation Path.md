# Mandrake project make-up and simulation path

Use this path after an absence or when assigned hardware is unavailable. It preserves the same goal and scoring evidence.

1. Read the project brief and current 90-point rubric.
2. Create the same purpose, user need, component list, and input-process-signal-output flow.
3. Build the sensor logic in MakeCode simulator when possible. If MakeCode is unavailable, create labeled pseudocode or a paper block sequence.
4. Use `distance > 18 cm`. Trace 17 cm → no alert, 18 cm → no alert, and 19 cm → `ALERT` plus sound. Trace 19 cm three more times for reliability.
5. Record one controlled change and predicted retest.
6. Submit the saved simulation/share link or paper logic, project log, test record, demonstration explanation, and reflection.
7. Complete a live explanation or teacher-scheduled computer/paper explanation. Do not use a phone, photo, screenshot, or open-web source.

The teacher scores the same seven rubric criteria. Physical hardware performance is represented by the labeled simulation and test evidence, not omitted. The six academic criteria score the project work. The 9-point readiness criterion may reflect a forgotten or uncharged personal device, unprepared login, lateness, or missed checkpoint. A documented school, platform, teacher-provided account, connection, or hardware failure outside the student's control does not reduce readiness points when this path is completed.
