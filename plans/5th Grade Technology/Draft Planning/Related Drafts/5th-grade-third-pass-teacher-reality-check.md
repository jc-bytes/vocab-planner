## 1. Classroom Flow Check

Overall result: ready with normal teacher preparation.

| Check | Result |
| --- | --- |
| Pre-Activities fit 10-15 minutes | Yes. Each class has practice keywords plus 1-2 short warm-up tasks. |
| While Activities are the center | Yes. Each class has a main task, check, practice build, drawing, sorting task, quiz, or demo. |
| Post-Activities fit 5-10 minutes | Yes. Closures are mostly submit, share, write one idea, store materials, or choose one make-up item. |
| One clear main purpose | Yes. Lessons stay focused on one class goal. |
| Tool/task switching | Mostly safe. The highest-switching lessons are hardware test/demo days and computer-based chart/vector days. |
| Clear closure action | Yes. Each class ends with a submission, reflection, share-out, storage step, or organization step. |

Lessons most at risk of taking too long:
- T1 W8 Class 2, Worm Robot Test and Demo: robot setup and group demos may run long.
- T1 W10 Class 2, Telescopic Clamp Testing: hardware testing may need setup time.
- T1 W11 Class 2, Propeller Aircraft Short Demo: materials and safety routines may slow the class.
- T2 W8 Class 2, Visual Media Product Sharing: one-minute presentations can run long with a large group.
- T3 W4 Class 2, Database Search and Chart Task: chart creation may run long if the tool is unfamiliar.
- T3 W8 Class 2, Vector Product Sharing: sharing time depends on class size.

Suggested teacher move:
- Use small-group demos or rotating stations for robotics.
- Use a timer for product sharing.
- Prepare printed or projected examples before computer-based chart/vector lessons.

## 2. Student Understanding Check

Overall result: ready.

The plans now support student understanding because every class includes 1-2 practice keywords with definitions, examples appear before independent checks, and the tasks use concrete verbs such as match, draw, sort, label, test, record, submit, and present.

Vocabulary reuse is strongest in these progressions:
- Robotics: robot, sensor, motor, controller, sequence, command, path, obstacle, mechanism, input, output, condition.
- Systems and search: input, process, output, connection, keyword, source, ranking, advertisement, reliable.
- Media: visual, message, audience, purpose, storyboard, panel, caption, presentation, feedback.
- Databases and drawing: field, record, database, sort, group, table, filter, chart, vector, layer, group.
- Selection/debugging: condition, outcome, selection, true, false, debug, logic error.

Remaining teacher watch-outs:
- `K96131`, `Telescopic Clamp`, and `Propeller Aircraft` need real pictures, parts, or sample models before students work independently.
- `database`, `filter`, `vector`, and `selection` should always be shown with an example first.
- Scratch/Blockly lessons should have a paper fallback if accounts or computers fail.
