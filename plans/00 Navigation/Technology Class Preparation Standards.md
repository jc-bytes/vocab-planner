# Technology Class Preparation Standards

## Purpose

A written monthly or annual plan describes intended teaching. A prepared lesson package contains everything required to teach, practice, assess, review, score, and recover the class.

A class is not fully prepared until its required materials exist, open correctly, agree with one another, and have been checked from the student and teacher perspectives.

## Plain-Language Methodology

Use the spirit of `Explain it like I'm five`: explain ideas in the simplest clear form without talking down to students or removing the grade-appropriate thinking. Clear language is part of instructional quality, not an optional style preference.

Apply these rules to titles, objectives, Classroom posts, slides, handouts, modules, templates, examples, checklists, rubrics, review materials, make-up work, and teacher guides:

- Use a short, literal student-facing title, usually two to six words.
- Prefer `Topic + Task/Product` or `Verb + Product`, such as `Internet Safety Poster`, `Build a Data Chart`, or `Scratch Score Game`.
- Avoid long academic titles such as `Exploration of Digital Citizenship Principles Through Visual Communication` when a simpler title communicates the same task.
- Use familiar words, active voice, and short sentences.
- Put one main action in each numbered step.
- Begin student directions with direct verbs such as `Open`, `Write`, `Add`, `Create`, `Check`, `Save`, `Download`, and `Submit`.
- Define a necessary technical term before asking students to use it. Remove jargon that is not part of the lesson.
- Replace vague words with exact counts, names, dimensions, formats, examples, and visible evidence.
- Keep paragraphs short and use headings or lists when they make the sequence easier to scan.
- Keep teacher-facing writing concise and operational. Define uncommon abbreviations and make the next action obvious.

Do not oversimplify the learning objective. Simplify the wording while preserving the real concept, required evidence, and grade-level challenge.

Before marking student-facing material `Ready`, apply the first-read test. A student should be able to answer:

1. What do I do first?
2. What am I making or showing?
3. What must it include?
4. What do I submit?
5. How do I know I am finished?

If the student must reread the directions to discover a required product, count, file, or submission step, revise the writing.

## Readiness States

- **Draft:** The lesson sequence, objective, or assessment is still being decided.
- **Materials Missing:** The lesson is described, but one or more required artifacts do not exist or have not been checked.
- **Needs Revision:** The artifacts exist but conflict, contain unclear requirements, fail validation, or do not fit the lesson.
- **Ready to Teach:** The plan and all required artifacts are aligned, verified, and usable by the teacher or a substitute.

An official monthly-plan DOCX can be document-complete while its lessons remain **Materials Missing**.

## Standard Package for an Instructional Class

Every regular class should have, as applicable:

1. Teacher lesson guide with timing and setup.
2. Presentation or appropriate visual teaching aid.
3. Student handout, digital task, or reference material.
4. Paste-ready Google Classroom assignment instructions when students must create, complete, demonstrate, or submit work through Classroom.
5. Editable template or starter file when setup must be controlled.
6. Completed example or expected output for new or multi-step work.
7. Guided or independent practice.
8. Teacher answer key or expected responses.
9. Exit ticket or another explicit understanding check.
10. Make-up path for absent students.
11. Offline or technology-failure alternative.
12. Package manifest recording exact filenames and readiness.

The visual aid may be a full teaching deck, a short work-session deck, or a clearly labeled section of a shared deck. It must still guide the specific class.

## Reusable Learning Modules

A verified web-based learning module may satisfy several student-facing package items, such as visual explanation, reference material, guided practice, independent practice, formative checkpoint, review, or make-up support.

Reference modules by exact ID, version, section IDs, and track:

```text
MOD-PY-DATA-01 v1.2.0, Sections S1-S3, Core track
```

Do not reference only `Python website`, `data module`, or a page title. Only modules marked **Ready** in the central catalog count as prepared resources. A **Pilot** module requires monitoring and a complete fallback.

The class package must still provide the teacher guide, assigned sections, class timing, local prompts, submission instructions, formal scoring tool when applicable, and offline/technology-failure path. Record exactly which module sections replace which package artifacts.

## Standard Package for a Formal Assessment

Every formal grade should include:

1. Paste-ready Google Classroom assignment instructions containing the complete student-facing directions.
2. Yes/no submission checklist.
3. Rubric or answer key. When the scoring tool is a rubric, provide both the official school DOCX and a score-equivalent Google Classroom import XLSX.
4. Required template, starter file, dataset, images, code, or source materials.
5. Completed example, model, or expected output when appropriate.
6. Practice using the same knowledge, tool, or product type before assessment.
7. Review material covering the assessed knowledge.
8. Teacher-only scoring notes or answer key when needed.
9. Make-up or alternative evidence path.
10. Exact file-naming and submission instructions.

Every scored requirement must appear in the directions. Every required deliverable must map to a rubric criterion, checklist item, or explicit non-scored submission check.

The Classroom rubric is a required paired deliverable for a finalized rubric unless the teacher explicitly requests Word-only output. It must preserve the same criteria, performance levels, thresholds, zero-score conditions, maximum points, and total score as the DOCX. A formal-assessment package is not **Ready to Teach** when the Classroom file is missing, invalid, or out of sync.

## Google Classroom Assignment Contract

Any task students are expected to complete, demonstrate, or submit through Google Classroom needs a paste-ready assignment file. Use `Google Classroom Assignment Instructions.md` or a clearly named package equivalent. It is an authored student artifact, not a teacher reminder or a shortened summary.

The Classroom post must be complete enough that an absent student can understand and complete the assignment using only the post and its attached files. Include, as applicable:

- exact product, performance, or evidence students must submit
- required title or exact wording when necessary
- required sections, content, labels, examples, images, sources, screenshots, code, data, or demonstrations, including exact counts
- size, orientation, duration, file type, and required filename
- fixed visual or structural requirements and clearly labeled areas of student choice
- exact template, starter file, dataset, module section, software, hardware, or source material to use
- ordered steps written with student-facing action verbs
- individual and group responsibilities
- where and how to submit, including whether links, files, screenshots, or in-person demonstrations are required
- deadline or class-period language supplied by the teacher or approved plan
- yes/no submission checklist
- rubric name, point value, and attached Classroom rubric when applicable
- make-up path and what to do when the normal device, account, internet, software, or hardware is unavailable

Do not publish vague directions such as `Make a poster about internet safety`, `Complete the project`, or `See the rubric for details`. The rubric may explain scoring levels, but it may not introduce requirements absent from the Classroom directions.

Use a short Classroom title that names the task or product. Keep the post easy to scan with short sections and numbered actions. Do not copy formal curriculum language into the student post when a familiar phrase communicates the same meaning.

Maintain one approved assignment specification for each task. The Google Classroom post, student handout, template, completed example, presentation task slides, checklist, rubric DOCX, and Classroom rubric XLSX must express that same specification. Do not independently paraphrase consequential requirements in each artifact.

Use this alignment test before posting:

```text
Google Classroom directions
  -> template/starter file
  -> completed example or expected output
  -> submission checklist
  -> rubric criteria and points
  -> submitted evidence
```

Every required element must be supported by the template when one is supplied, visible in the model when appropriate, checked by the checklist, and either scored or explicitly labeled as a non-scored submission requirement. Every scored requirement must appear in the Classroom directions. If one artifact changes, recheck and update the entire chain before posting.

## Objective Assignment Specifications

Directions should state all consequential requirements before students begin. Depending on the activity, specify:

- exact product or performance
- required title or wording
- required sections and number of elements
- required images, examples, sources, screenshots, code, data, or demonstrations
- size, orientation, duration, file type, and filename
- required template, tool, dataset, or hardware
- allowed resources
- submission location and format
- individual evidence for group work
- language, safety, source-credit, or presentation rules

Do not prescribe decorative choices unless they serve the learning objective, accessibility, brand requirement, or explicit teacher decision. When choice is valid, use objective functional requirements such as readable contrast, consistent formatting, and no overlapping elements.

## Objective Rubric Rules

Use this test for every criterion:

> Could two teachers independently inspect the same submission and assign approximately the same score using only the directions and descriptors?

Prefer:

- exact counts and complete score ranges
- named required parts
- correct/incorrect or working/not-working checks
- accuracy thresholds
- visible labels, screenshots, sources, files, or demonstrations
- clear missing, incomplete, unreadable, unsafe, or not-submitted conditions

Do not let words such as excellent, good, creative, attractive, professional, some effort, or mostly correct determine a score without observable evidence.

Use short criterion names and plain descriptors. A student should understand what evidence earns each score without needing the teacher to translate the rubric.

Do not double-penalize the same missing evidence in unrelated criteria.

## Games and Review Activities

If a plan says Blooket or Gimkit, the import file must exist before the lesson is ready. The package must include:

- import-ready CSV
- verified correct-answer source
- teacher game-mode and timing note
- student review material from which questions were drawn
- printable or offline alternative

Questions must come from previously taught or student-provided content. Assessment review must align with the directions and rubric without revealing private answers.

## Accessibility, Differentiation, and Recovery

Each package should account for:

- students who need guided steps
- students who finish early
- students who were absent
- broken or unavailable devices
- account, internet, software, or hardware failure
- reduced class time
- printed alternatives when needed
- individual accountability during group work

The alternative activity must preserve the objective and comparable evidence. It should not become an easier unrelated task.

## Private Teacher Materials

Keep answer keys, scoring notes, private datasets, and student information in a clearly labeled teacher-only location. Check every student template, presentation, handout, shared folder, and exported file for accidental answer exposure.

## Required Alignment Chain

```text
Objective -> instruction -> modeled example -> practice -> Google Classroom directions/student task -> submitted evidence -> scoring -> review/make-up
```

Repair any break before declaring the class ready.

## Final Ready-to-Teach Checks

- All required files exist and open correctly.
- Exact filenames or stable material IDs appear in the manifest.
- The presentation and handout give the same instructions.
- A paste-ready Google Classroom assignment exists for every Classroom task and contains no teacher placeholders.
- Student-facing titles are short and literal, and the first-read plain-language test passes.
- Directions use familiar words, direct verbs, short sentences, and one main action per step.
- Necessary technical terms are explained before students must use them.
- The Classroom post, presentation task slides, handout, template, example, checklist, and rubric state the same consequential requirements.
- The template supports every required deliverable.
- The completed example follows the directions and earns the intended rubric level.
- The DOCX rubric and Google Classroom XLSX have matching criteria, score bands, special conditions, and total points.
- The Classroom workbook passes structural validation, contains no formulas, and has been visually checked after export.
- Practice occurs before assessment.
- Review covers what will be assessed.
- The activity fits the scheduled time.
- The make-up and technology-failure paths preserve the objective.
- Student materials contain no private answer keys.
- A student can identify the first step and submission requirements.
- An absent student could complete the assignment using only the Classroom post and attached student files.
- A substitute teacher could deliver the class tomorrow without creating missing materials.
