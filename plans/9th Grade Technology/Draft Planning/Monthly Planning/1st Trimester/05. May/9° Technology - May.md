# 9th Grade Technology - May 2026

## Monthly Focus
Students finish the robotics learning sequence by documenting design decisions, completing the fifth daily grade, and using weeks 10-12 for the trimester robotics exam project. Week 13 is reserved for exams, make-up work, and administration.

## Weekly Time
- Class 1: 45 minutes
- Class 2: 90 minutes
- Weekly total: 135 minutes

## Competences

- Design a robotics system with a clear goal, constraints, component list, state chart, inputs, outputs, and test cases.
- Build, test, debug, and improve a robotics prototype using controlled trials, project-log evidence, and feedback.
- Present a technical explanation that connects inputs, logic, outputs, state changes, reliability evidence, and improvements.

## Learning Objectives

- Create a robotics design plan that defines the goal, controls, outputs, states, components, risks, and test cases before building.
- Build and debug the exam robotics project across multiple sessions using test notes, failure evidence, and improvement goals.
- Explain how inputs, logic, outputs, components, reliability, and team roles work together in the final system.

## Learning Outcomes

- Submit a robotics design plan with goal, inputs/controls, outputs, state chart, components, risks, and test cases.
- Build and improve the exam robotics prototype during Weeks 10-11 using documented testing evidence.
- Present the robotics project in Week 12 using a project log, state logic explanation, test evidence, and reflection.

## Evaluation
- Daily Grade #5 in Week 9: robotics design plan.
- Exam Project begins Week 10, continues Week 11, and presents Week 12.
- Week 13 reserved for exams/admin.

## Vocabulary Plan
### Practice Vocabulary

#### Week 9: Robot Design

| Word | Simple Definition |
| --- | --- |
| robot goal | What the robot should do. |
| component list | A list of parts needed for a project. |
| state chart | A table or diagram showing states and actions. |
| design plan | A plan for building and testing a project. |
| test step | One action used to check if something works. |
| feedback | Helpful comments about how to improve. |

#### Week 10: Project Build

| Word | Simple Definition |
| --- | --- |
| subsystem | One smaller part of a larger system. |
| wiring | How electronic parts are connected. |
| code logic | The rules and order used in code. |
| documentation | Notes or records that explain work. |
| test result | What happened during a test. |
| debug | To find and fix a problem. |

#### Week 11: Reliability

| Word | Simple Definition |
| --- | --- |
| reliability | How dependably something works. |
| code comment | A note in code that explains something. |
| controlled test | A test where conditions are carefully chosen. |
| pass/fail | A result showing whether something worked or not. |
| weak point | The part that needs the most improvement. |
| improvement | A change that makes something better. |

#### Week 12: Demonstration

| Word | Simple Definition |
| --- | --- |
| demonstration | Showing how something works. |
| reflection | Thinking about what happened and what you learned. |
| testing evidence | Proof from tests that shows what happened. |
| state logic | Rules for how a system changes between states. |
| project log | A record of project work and tests. |
| presentation | Sharing work or ideas with others. |

| Word | Simple Definition |
