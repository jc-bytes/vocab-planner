Quick reference

A user has a specific task. A feature addresses part of the user's problem. A screen has one main job. An event connects a user action to an app response. A test case states a starting condition, action, expected result, and pass rule.

Practice 1: users and features

School event reminder: Students miss club meetings and deadlines because details are spread across several messages.

  1. Name a specific user and task.
  2. State the problem without naming a solution.
  3. Propose one feature that addresses the problem.
  4. Write a measurable success criterion.
  5. Divide the app into at least three user jobs.

Practice 2: screens and events

Library seat reservation: A student chooses a date and time, selects an available seat, and submits a reservation. The app must stop blank or unavailable choices.

  1. Name three screens and the job of each.
  2. Place at least five interface elements on those screens.
  3. Write four event mappings as action → response.
  4. Name two stored values and when each changes.
  5. Write feedback for one successful and one failed action.

Practice 3: test cases

Cafeteria preorder: Students select one meal and pickup time. The app must not save incomplete orders or unavailable meals.

  1. Test that Order opens the correct screen.
  2. Test a complete valid order.
  3. Test one required field left blank.
  4. Test an item with zero portions remaining.
  5. Write a retest after a blank order bug is fixed.
