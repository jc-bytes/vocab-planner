# Python Input, Arithmetic, and Debugging teacher guide

**Module:** MOD-PYTHON-FUNDAMENTALS-01 v0.1.0  
**Grades:** Grade 8  
**Status:** Pilot  
**Evidence:** Saved attempts, application record, and exported HTML practice report

## Before class

- Open the assigned module route and verify the required section IDs.
- Prepare Python editor or browser-based runner and fixed starter code.
- Each practice page contains five code, run, trace, or debug activities on one screen. Students use the assigned Python editor and save the exact evidence in the module.
- Keep the printable fallback ready.
- Remind students that progress stays on the current browser and device. They should export before changing computers.

## Teaching pattern

1. Use 5 minutes for the objective and one retrieval question.
2. Teach one Learn section for 10-15 minutes while students follow on their computers.
3. Model one full cycle: predict, run, read the output or message, correct one cause, and retest.
4. Assign the matching Practice section for 35-45 minutes. Students should run code when Python is available and trace it when it is not.
5. Review one common error. Students then complete or update the application record.
6. Use the final 5 minutes to export evidence or record the stopping point.

Do not assign the whole module in one period. Monthly plans name the exact sections for each class.

## What to check

Check the saved `.py` file, numeric input conversion, three calculations, labeled output, exact error correction, and tests that compare expected with actual results.

## Misconceptions

Students add strings and numbers; confuse assignment with comparison; change code without reading the error.

## Differentiation

- Ask students who need support to explain one decision aloud before selecting an answer.
- Let students revise saved responses after running another test. Updated work remains available for export.
- Students ready for extension should justify why one rejected option fails or create a new test case using the same rule.

## Make-up and fallback

An absent student completes the same assigned Learn and Practice sections, then exports the report. The printable fallback contains all arithmetic, debugging, calculator, and application tasks. If Python is unavailable, students trace values and expected outputs by hand. Evidence comes from the saved Python file and typed test record.

## Pilot notes

Record actual completion time, unclear wording, repeated wrong answers, device problems, and whether the fallback produced comparable evidence. Keep the module at pilot status until classroom observations have been reviewed.
